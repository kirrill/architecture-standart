| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | На сайте клиенту отображается список доступных депозитов с актуальными ставками                       |              |
| F2  | Клиент может подать заявку на депозит, оставив свой номер телефона и Ф. И. О. на сайте               |              |
| F3  | Интеграция сайта с кол-центром для передачи заявок  |              |
| F4  | В интернет-банке клиенту отображается: список доступных депозитов с актуальными ставками и персонализированные ставки лично для него  | |
| F5  | Клиент может подать заявку на открытие депозита в интернет-банке указав счет и сумму депозита и подтвердив по СМС|              |
| F6  | Ведение ставок по депозитам (включая процесс согласования ставок) в АБС | |
| F7  | Отправка CМС-уведомлений клиенту (подтверждение ставки, открытие депозита)
| U   | Удобство использования (Usability) |              |
| U1  | Интерфейс должен соответствовать корпоративному дизайну (цвета, брендинг).                               |              |
| U2  |  Адаптивный дизайн сайта и интернет-банка для мобильных устройств | Т.к. большинство пользователей сейчас использует мобильные устройства для доступа в интернет |
| R   | Надёжность (Reliability)           |              |
| R1  | Режим работы 24/7 (SLA 99,9%)      |              |
| R2  | Обеспечить переключение на резервный ЦОД при сбоях |              |
| R3  | Обеспечить мониторинг и алертинг | Для быстрого реагирования на внештатные ситуации |
| P   | Производительность (Performance)   |              |
| P1  | Время отклика страниц должно занимать меньше секунды   | Потребуется оптимизация справочников   |
| P2  | Возможность горизонтального масштабирования | Кроме АБС, которая может масштабировать только вертикально из-за БД|
| P3  |  Распределение нагрузки между серверами и ЦОД |              |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Обеспечить совместимость с текущими платформами разработки при внедрении новых технологий |              |
| S2  | Ведение документации для дальнейшего расширения системы    |              |
| S3  | Обеспечить логирование ключевых действий в системах | Для поиска причин ошибок |
| +R  | + Ограничения (Restricitions)      |              |
| +R1 | Отдать предпочтение СУБД MS SQL и Oracle при доработках систем |           |
| +R2 | Доработки систем выполнять с использовнием текущего стека технологий: Фронтенд - React; Бекэнд - Java Spring Boot, ASP.NET |     |
| +R3 | Функционал по открытию депозитов в АБС можно реализовать с применением микросервисной архитектуры    |              |
| +R4 | При необходимости использования очередей сообщений - использовать Apache Kafka  | Но иметь ввиду, что текщуая версия платформы интернет-банка не совместима с Kafka |
| +R5 | Ограничение нагрузки на систему АБС (избегать прямых вызовов API). | |
| +R6 | Требуется доработка функционала работы с СМС. Желательно выполнить силами команды разработки банка |              |
| +R7 | Обеспечить шифрование трафика между сайтом, интернет-магазином и сервером|     |
| +R8 | Разработать механизм мультифакторной аутентификации (минимум двухфакторной через отправку СМС с кодом потверждения) пользователей интернет-банка | Для повышения безопасности |
| +R9 | Обеспечить соответсвие ФЗ 152 и требованиям ЦБ РФ | Для соответвия требваниям законодательства и регулятора |
